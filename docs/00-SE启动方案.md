## 0. 一页读懂

**做什么**：一个浏览器里打开就能用的简历生成器。左边是模块仓库，中间是 A4 纸张画布，右边是当前模块的编辑面板。模块能拖动、能排序、能在单栏/双栏之间搬移，头像能上传，最后点一下导出成矢量文字 PDF。

**技术底座**：React 19 + Vite 6 + TypeScript + Tailwind CSS 4 + `@dnd-kit`；数据存 localStorage，JSON 可导入导出；PDF 走浏览器原生打印管道。

**工程上最关键的一句话**：所有功能都以「模块（Block）」为唯一扩展单位——每加一个简历模块，只新增一个目录 + 注册表一行，不改画布、不改拖拽、不改导出。这是"模块化"能不能成立的分水岭。

**交付节奏**：M1 骨架 → M2 数据层 → M3 模块编辑 → M4 拖拽 → M5 模板主题 → M6 打印导出 → M7 头像与备份 → M8 验收。

## 2. 技术选型与理由

| 层 | 选型 | 版本策略 |
|---|---|---|
| 构建 | Vite | 安装时锁定最新稳定版，写进 `package-lock.json` |
| 框架 | React + TypeScript | 同上，TS 开 `strict` |
| 样式 | Tailwind CSS（编辑器 UI）+ 原生 CSS（简历模板与打印） | 二者边界严格分离，见 3.7 |
| 状态 | Zustand + `persist` 中间件 | — |
| 拖拽 | `@dnd-kit/core` + `@dnd-kit/sortable` | — |
| ID | `nanoid`（10 位） | — |
| 图标 | `lucide-react` | — |
| 校验 | 手写轻量校验（无 zod，见下） | — |

**为什么不用更流行的方案**

- **不用 `react-beautiful-dnd`**：项目已被归档停止维护，与 React 19 的 StrictMode 存在兼容问题。`@dnd-kit` 至今在维护，且原生支持多容器拖拽（正好是双栏需求）与键盘无障碍。
- **不用 `html2canvas + jsPDF`**：导出结果是位图，文字不可选、体积大、ATS 简历系统解析失败率高。浏览器打印管道输出的是真矢量文字。
- **不用 Redux Toolkit**：本项目只有一个文档树 + 一个选中态，Redux 的样板代码成本远大于收益。Zustand 的 `persist` 自带版本迁移，正好覆盖数据结构演进。
- **不用 Next.js**：无服务端需求，SSR 只会增加构建与部署复杂度。
- **不用富文本编辑器（Tiptap/Lexical）**：简历描述本质是「要点列表」，富文本带来的样式漂移会直接破坏 A4 分页。首版用「纯文本 + 一行一条」换取排版确定性。
- **不引入 zod 做校验**：首版校验只发生在两个边界（导入 JSON、表单输入），手写 200 行足够，省掉一个运行时依赖。

## 3. 架构设计

### 3.1 分层

```
表现层（UI/交互）      features/*, blocks/*/Renderer|Editor, components/ui
      │  只读 doc、只发 action
领域层（规则/类型）    domain/*（类型、默认值、注册表、迁移）
      │  纯函数，不碰 DOM、不碰 React
持久层（存储）         store/（zustand persist） → localStorage
```

铁律三条：
1. **领域层不 import React**，保证类型与规则可单测。
2. **Renderer 不持有状态**，只吃 `data + theme` 两个入参，因此编辑器预览和打印输出可复用同一组件 —— 这是「所见即所得」的唯一保证方式。
3. **所有写操作走 action**，组件不直接改 `doc`。拖拽、删除、编辑都收敛到 `store/actions.ts`，便于回滚与撤销。

### 3.2 数据模型（归一化，完整定义）

```ts
// src/domain/types.ts

export type BlockType =
  | 'profile' | 'summary' | 'experience' | 'education' | 'projects'
  | 'skills' | 'awards' | 'certificates' | 'languages' | 'custom'

export type ColumnId = 'main' | 'side'

export interface ResumeDoc {
  schemaVersion: 2                  // 结构版本，用于 migrate
  id: string                        // nanoid
  title: string                     // 简历名称，默认 "我的简历"
  updatedAt: string                 // ISO 8601
  theme: ThemeConfig
  layout: LayoutConfig
  blocks: Record<string, Block>     // 归一化：id -> 模块
}

export interface LayoutConfig {
  mode: 'single' | 'sidebar-left' | 'sidebar-right'
  sidebarWidthPct: number           // 28 | 33 | 38，仅双栏生效
  order: Record<ColumnId, string[]> // 列内顺序 = 模块 id 数组（唯一真源）
}

export interface ThemeConfig {
  templateId: 'classic' | 'modern' | 'compact'
  accent: string                    // hex，默认 #2563EB
  fontFamily: 'system-sans' | 'system-serif'
  baseFontSizePx: number            // 12–16，默认 14
  lineHeight: number                // 1.3–1.8，默认 1.6
  density: 'compact' | 'normal' | 'loose'
  pagePaddingMm: number             // 10–20，默认 15
  showIcons: boolean
}
```

模块基类与各模块数据（判别联合，`type` 决定 `data` 形状）：

```ts
interface BlockBase<T extends BlockType, D> {
  id: string
  type: T
  visible: boolean        // false = 保留数据、不渲染、不打印
  data: D
}

export type Block =
  | BlockBase<'profile', ProfileData>
  | BlockBase<'summary', SummaryData>
  | BlockBase<'experience', ExperienceData>
  | BlockBase<'education', EducationData>
  | BlockBase<'projects', ProjectsData>
  | BlockBase<'skills', TagsData>
  | BlockBase<'awards', AwardsData>
  | BlockBase<'certificates', CertificatesData>
  | BlockBase<'languages', LanguagesData>
  | BlockBase<'custom', CustomData>

export interface ProfileData {
  name: string; headline: string          // headline = 一句话职位定位
  avatarUrl: string | null                // dataURL(jpeg) 或 null
  email: string; phone: string; location: string
  links: { id: string; label: string; url: string }[]   // 最多 4 条
}

export interface SummaryData { text: string }             // 纯文本，\n 视为换行

export interface ExperienceItem {
  id: string
  company: string; role: string; location: string
  start: string; end: string; current: boolean            // 'YYYY-MM'
  bullets: string[]                                        // 一行一条，最多 8 条
}
export interface ExperienceData { items: ExperienceItem[] }

export interface EducationItem {
  id: string; school: string; degree: string; major: string
  start: string; end: string; detail: string
}
export interface EducationData { items: EducationItem[] }

export interface ProjectItem {
  id: string; name: string; role: string; period: string
  description: string; tech: string[]; highlights: string[]
}
export interface ProjectsData { items: ProjectItem[] }

export interface TagsData {
  groups: { id: string; label: string; items: string[] }[]  // 如「语言 / 前端 / 工具」
}
export interface AwardsData { items: { id: string; title: string; date: string; issuer: string }[] }
export interface CertificatesData { items: { id: string; name: string; date: string; issuer: string }[] }
export interface LanguagesData { items: { id: string; name: string; level: string }[] }
export interface CustomData { title: string; items: { id: string; text: string }[] }
```

**为什么归一化**：`blocks` 用 map + 列内 id 数组，拖拽只需移动数组下标，不必全树重建；删除模块只需两处（map 删键、order 删 id），不存在"孤岛数据"；迁移时也能逐块处理。

### 3.3 模块注册表（模块化的唯一扩展点）

```ts
// src/domain/blocks/registry.ts
export interface BlockModule<D = unknown> {
  type: BlockType
  label: string                                  // 仓库里的显示名
  description: string
  icon: LucideIcon
  createDefault: () => Block                     // 新建时的初始数据
  Editor: React.FC<{ data: D; onChange: (patch: Partial<D>) => void }>
  Renderer: React.FC<{ data: D; theme: ThemeConfig }>
  isEmpty?: (data: D) => boolean                 // 空模块不打印（避免导出空白标题）
}

export const BLOCK_REGISTRY: Record<BlockType, BlockModule<any>> = { /* 10 项 */ }
export const PALETTE_ORDER: BlockType[] = ['profile', 'summary', 'experience', /* ... */]
```

画布渲染、仓库列表、Inspector 全部通过 `BLOCK_REGISTRY[block.type]` 取组件，**没有任何 switch-case 硬编码模块**。新增「出版物」模块的完整成本 = 新建 `src/blocks/Publication/{index,Editor,Renderer}.tsx` + 在注册表加一行 + 在 `types.ts` 加一个联合成员。

### 3.4 拖拽模型

- `DndContext` 全局唯一，挂在 `features/layout/ColumnCanvas.tsx`。
- 两个 `SortableContext`（`main` / `side`），`items` 直接取 `layout.order[columnId]`。
- 传感器：`PointerSensor`（`activationConstraint.distance = 4`，避免点击被当作拖拽）、`KeyboardSensor`（可达性）。
- 跨容器落位：`onDragOver` 里做「预移动」把 id 从源数组摘到目标数组，`onDragEnd` 只做最终提交。这样拖拽过程中预览实时正确。
- 单栏模式下 `order.side` 必须为空，切回双栏时把 `side` 中残留模块按原顺序合并到 `main` 末尾 —— 由 `layout.ts` 的 `normalizeLayout()` 统一收口，避免出现"数据在但看不见"。

### 3.5 打印 / PDF 管线

```
点击「导出 PDF」
  → flush 自动保存 + await document.fonts.ready
  → 切换到 print 专用根节点（渲染同一套 Renderer，theme 相同）
  → window.print()（用户选「另存为 PDF」）
  → 打印结束恢复编辑态
```

关键 CSS 契约（`src/lib/print.css`）：

```css
@page { size: A4; margin: 0; }

@media print {
  body > *:not(#print-root) { display: none !important; }   /* 藏掉编辑器 UI */
  #print-root { display: block !important; }
  .resume-page {
    width: 210mm; min-height: 297mm;
    padding: var(--page-pad);                                /* 变量来自 theme */
    box-shadow: none; margin: 0;
    -webkit-print-color-adjust: exact; print-color-adjust: exact;
  }
  .block { break-inside: avoid-page; }                       /* 一个模块不被腰斩 */
  .block__title { break-after: avoid; }                      /* 标题不落在页底 */
  .item { break-inside: avoid; }                             /* 单条经历不跨页 */
}
```

尺寸换算（写死在 `domain/constants.ts`，全项目唯一）：
`1mm = 96/25.4 = 3.7795px`；`210mm = 793.7px`；`297mm = 1122.5px`。屏幕用 px 定宽 + `transform: scale(zoom)`，打印用 mm，两者不混用。

### 3.6 图像处理管线（头像）

```
File → 类型/大小校验(≤5MB) → createImageBitmap
     → 居中裁切正方形（取 min(w,h)）
     → 缩放到 max 512×512
     → canvas.toDataURL('image/jpeg', 0.82)
     → 若 >120KB 则降 quality 到 0.7 重编码一次
     → 失败(仍 >300KB) → 拒绝并提示换图
```

存 dataURL 而非 Blob URL：`localStorage` 只存字符串，Blob URL 刷新即失效。

## 4. 关键规则

### 4.1 自动保存

- 触发：任何 action 改 `doc` → `updatedAt` 更新 → 600ms 防抖写 localStorage。
- Key：`rb:doc:v1`；`persist` 的 `version: 2` 与 `migrate` 绑定 `schemaVersion`。
- 容量：写前 `navigator.storage.estimate()` 检查，剩余 <500KB 时弹提示「导出 JSON 备份后清理」。
- 兜底：`beforeunload` 时若有未落盘改动，`event.preventDefault()` 提示。

### 4.2 迁移

```ts
// migrate.ts
export function migrate(raw: unknown): ResumeDoc {
  // v1 → v2：blocks 从数组改为归一化 map + order
  // 任何无法识别的字段一律丢弃，缺失字段用 defaults 补齐
}
```
导入 JSON 时先 `migrate` 再做结构校验，校验失败给具体错误（"第 3 个模块缺少 type"），不静默吞掉。

### 4.3 空态

- 无任何模块：画布中央显示引导「点击左侧模块开始」。
- 模块内无内容：Renderer 返回 `null`（配合 `isEmpty`），避免导出只有标题的空段落。

## 9. 实施差异记录（v1.0 方案 → 实际交付）

方案落地时有三处主动调整，均已在代码中生效：

| 方案原定 | 实际实现 | 原因 |
|---|---|---|
| 每个模块 `{index,Editor,Renderer}.tsx` 三文件 | 每个模块一个 `index.tsx`（含 Renderer + Editor + 模块对象） | 模块是叶子组件，单文件自包含更易读；扩展成本仍是「1 个目录 + 注册表 1 行」 |
| `templates/{classic,modern,compact}.css` 三份 | 合并为 `styles/resume.css` 内的 `.tpl-*` 作用域 | 三套模板共享 80% 规则，拆文件后极易改一处漏两处 |
| `.block { break-inside: avoid-page }` 整块不分页 | 改为「标题不与正文分离 + 单条目/单要点不跨页」 | 整块不分页会让 5 条经历的大模块整体被推到下一页，留下半页空白 |

另外补充实现：打印时的 `@page` 页边距由 `lib/print.ts` 按当前页边距动态注入（`@page` 不支持 CSS 变量），`resume.css` 内保留 15mm/A4 兜底。
